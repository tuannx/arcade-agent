arch-demo: a deterministic smell laboratory

Real-world repos are noisy. So alongside the Django/React/Vue evaluation we built a tiny synthetic Python shop where two architectural smells are planted on purpose — then refactored away. Same pipeline, same changelog_architecture the GitHub Action uses. Deterministic by design: fixed sources, fixed outcome, reproducible with one command.

The setup

Before — smells planted

  • Dependency Cycle billing/invoice.py imports the notifier to send receipts, while notifications/emailer.py reaches back into billing to rebuild receipt lines → Billing ↔ Notifications.
  • Concern Overload utils/helpers.py: one god module, 20 unrelated helpers (strings, crypto, dates, http, files, money) with zero internal cohesion.
39 entities · 24 edges · 5 components · 2 smells

After — refactored

  • Cycle broken billing publishes an InvoiceIssued event; the orchestrator (orders/service.py) delivers it to notifications. Notifications now depends only on the event — one direction.
  • God module split only the 4 helpers actually used survive, in cohesive modules (text, crypto, timex); 16 dead helpers deleted.
20 entities · 22 edges · 5 components · 0 smells

Why a synthetic demo?

  • Deterministic. Real repos shift under your feet; this demo pins the exact sources, so the before/after diff is byte-stable and CI-friendly.
  • Pedagogical. Each smell is planted deliberately, so the report reads like a lab exercise: here is the disease, here is the cure, here is the proof.
  • Fast. The full pipeline runs in ~0.2 s — ideal for docs, talks, and the GitHub Action's own test suite.

Reproduce it

git clone https://github.com/tuannx/arcade-agent --branch gh-pages eval
cd eval/evaluation/synthetic
python run_synthetic.py   # analyzes before/after, diffs, writes HTML reports

Sources: before/ and after/ under evaluation/synthetic/ on the gh-pages branch. A GitHub Actions workflow (ci.yml) regenerates both reports on every push — one report per scenario, published here.
