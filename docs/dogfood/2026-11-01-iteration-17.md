## Finding and correction (not a verified architecture-policy violation)

Nested Python `class` base and `metaclass=` expressions execute when the class statement runs, in its **enclosing scope**. The previous conservative static analyzer skipped the entire nested `class_definition` AST subtree, so it missed actual same-module `helper()` call candidates in these expressions.

- Regression fixture: `tests/test_parsers/test_python_nested_class_bases_dogfood.py`.
- Tests-only RED commit `627f87891460575e799bc5944acd7b5bdc1ea173` and [RED CI 41390308642](https://github.com/tuannx/arcade-agent/actions/runs/41390308642): **2 failed, 878 passed, 3 skipped** on Python 3.12; the two positives both expected `app.parent → app.helper` but got `set()`. Python 3.13 cancelled after failure. [Job logs](https://github.com/tuannx/arcade-agent/actions/runs/41390308642).
- Implementation commit `ab4970bd8fc168d236f6330cf3ccaa365c10926c` and [GREEN CI 41390389732](https://github.com/tuannx/arcade-agent/actions/runs/41390389732): Python 3.12 and 3.13 **880 passed / 3 skipped each**, Ruff, packaging, self-analysis passed. **Two labelled true edges recovered**; deferred method body and shadowed-parameter negative controls remain without an edge; existing class decorator positive control preserved.
- Fix: visit only the nested class's `argument_list` (bases and metaclass keyword-value expressions) in the enclosing scope; never traverse the class body as if it belonged to its enclosing function. Class bodies, methods, attribute dispatch and dynamic calls remain out of this conservative model.
- An independent Python 3.13 standard-library runtime experiment confirmed definition-time base/metaclass evaluation; the real analyzer and test suite ran on GitHub-hosted CI, not in the local container.
- README now says Python's **unqualified same-module call extraction is partial**, rather than claiming full call coverage.
