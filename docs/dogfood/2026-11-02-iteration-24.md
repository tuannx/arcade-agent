## Bug, regression, limits

The ordered module-level inheritance scanner already suppresses stale edges when a superclass alias is reassigned, but did not recognize `del wire` or `del Parent`. After such deletion, accessing the name as a superclass raises at class definition time; it is incorrect to claim a known `extends` edge to the old import.

Fix: reuse the existing `_deletion_binding_names` helper in `_module_class_shadowed_names` for direct top-level `delete_statement`. Record an invalidated binding at the class-definition snapshot; a later import resets it. `del wire.marker` does **not** invalidate the `wire` binding. Bump per-file extractor cache `5 → 6` and full-graph schema `10 → 11` to prevent stale graph reuse.

Five new hand-labelled fixtures in `tests/test_parsers/test_python_module_del_superclass_dogfood.py`:
- **2 negative cases:** deleted module alias and deleted `from ... import ... as` superclass alias: stale `extends` edges **2 → 0**.
- **3 positive controls:** reimport after deletion, attribute deletion, deletion after the class: correct edges **3 → 3**.
- The static linker does not infer a dynamic replacement target, detect all conditional/re-export bindings, or prove runtime soundness. **Selected-fixture results are not production precision/recall or verified architecture violations.**
