## Finding, ground-truth labels, and correction

Python evaluates **lambda default argument expressions at callable creation time**, in the enclosing function's scope, but defers the lambda body. The prior conservative parser skipped the entire `lambda` subtree and therefore missed direct same-module call edges inside lambda defaults. The same issue was corrected for nested `def` defaults in iteration 15, but lambdas were still missing.

- New golden fixture: `tests/test_parsers/test_python_lambda_defaults_dogfood.py`.
- Positive labels: two genuine edges `app.parent → app.helper` (normal default and keyword-only default). Before fix **2 false negatives**; after fix **2/2 recovered**.
- Negative labels: three cases with no edge (deferred lambda body; outer parameter named `helper` shadowing module function; lambda default inside a nested function body deferred relative to its parent). All **3/3 negative controls** passed after fix; **0 false positives in these labelled controls**. No claim about production FP/FN rate.
- Parser change: visit only `default_parameter` / `typed_default_parameter` value subtrees of nested functions **and** lambdas, with enclosing scope; never traverse their deferred bodies. Unqualified-call coverage remains `partial`. Attribute/dynamic dispatch, implicit decorator application, class bases, and runtime resolution are not claimed complete.
- Independent Python **3.13 stdlib** runtime check confirms that `lambda value=helper(): value` runs `helper()` when its enclosing function constructs the lambda and not when the lambda is subsequently invoked.
- These are static dependency **candidates**, not verified architecture-policy violations. Zero reported heuristic smells in a target does not certify absence of violations.
