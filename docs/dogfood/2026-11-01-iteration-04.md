**Code/test head verified by CI:** `4d560c98553e374f1685fa0e001047c980419cd8`.
**GitHub PR merge checkout analyzed in hosted jobs:** `5689e553dcd6bb236fe7f1999cca1d351020cf00`. This is **not** the branch head or source target SHA.
**Base branch:** `dogfood/fix-source-commit-provenance-20261101` at `4fabc4cadbb706512da993b5b5b41191e61f6d14`.

### Root cause
The iteration-3 detector correctly downgraded shared class-name stems to **low-severity, naming-only candidates**, but `compute_balanced_scores()` still used every `SmellInstance` to calculate `SmellDiscipline`, `ResponsibilityFocus`, and `BalancedArchitectureScore`. A candidate with no verified harmful dependencies could lower the quality score.

### Fix
- Add `scoring_eligible: bool = True` to `SmellInstance` (default retains existing scoring semantics).
- Set `scoring_eligible=False` only for deterministic shared-name-stem candidates from `detect_scattered_functionality()`; the finding remains visible with its FQNs.
- Skip explicitly non-scoring candidates in `_smell_burden()`.
- Serialize the field to JSON so downstream consumers can distinguish candidate evidence from score inputs.
- Extend cross-repo workflow triggers when scoring code or its regression tests change.

**Boundary:** This change does not certify any other heuristic as a verified violation. The score remains a model with expert-chosen weights, not an empirical architecture-quality measurement.
