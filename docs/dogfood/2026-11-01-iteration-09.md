# Iteration 09 — Python binding shadows and private HA dogfooding (2026-11-01)

## Change and review boundary

PR [#19](https://github.com/tuannx/arcade-agent/pull/19) is a **draft stacked on #18**, which stacks on #17/#16/#15/#14. Do not merge automatically.

The Python parser in #18 made a same-module `calls` link when it saw a bare `helper()`, even when `helper` was actually bound locally by `with ... as helper`, `except ... as helper`, or `(helper := ...)`. A top-level `def helper` in the same file is not the callee in any of these cases.

The fix collects `as_pattern` / `except_clause` alias bindings, recognizes Tree-sitter's simple `as_pattern_target`, and reads the actual `name` field of `named_expression`. Call coverage remains **partial**. New cases include three negative controls and three positive unaffected call controls.

## Interpretation and follow-up

- The three red/green fixtures demonstrate **specific false call edges eliminated**, not a measured false-positive rate on human-labeled production code.
- Identical pinned-source Java/Python-examples graph metrics are expected: the scope-binding fix does not claim architecture improvement.
- The private target had **no prior baseline**; its first measurement cannot establish before/after improvement.
- Zero heuristic smells does **not** prove defect-free architecture. Both producer/replay jobs execute the same semantic analyzer: replay confirms reproducibility, not semantic correctness.
- Screenshot digest, PNG format and browser-capture step support artifact integrity/process provenance, but cannot cryptographically prove pixel-content authenticity.
- Next: generalize analyzer provenance for external CI runners and extend shadow-binding tests (destructuring, match patterns) without treating unresolved calls as verified edges. Keep PR #19 and the private workflow PR in draft; do not auto-merge.
