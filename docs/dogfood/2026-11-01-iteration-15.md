## Actual bug, labels, and scope of the correction

Python eagerly evaluates **default argument expressions of a nested function definition** in the enclosing function, but defers the nested function body and lambda bodies. The previously implemented `_extract_unqualified_calls` skipped all nested `function_definition` nodes, including their eager defaults. It therefore missed true same-module call edges for `def child(value=helper())` and `def child(value: int=helper())` inside a caller.

- **Golden fixture:** `tests/test_parsers/test_python_nested_defaults_dogfood.py` (three tests).
- **Prior evidence:** 2 expected positive call edges missed (false negatives), three negative controls suppressed (deferred nested body, lambda body, parameter-shadowed nested default). **0 false positives observed within these labelled controls; population FP/FN rate not measured.**
- **Fix:** visit only nested function default-value subtrees, in the enclosing scope. Continue skipping nested function/class/lambda bodies, annotations, dynamic dispatch and other unsupported cases. `call_coverage` stays `partial`. These are parser graph relationships, **not verified architectural violations**.
- Stdlib Python execution confirms `helper()` executes when the enclosing function defines the nested child, but not merely from defining the child body. The real `arcade-agent` analyzer was executed in hosted CI, not in the local sandbox (which lacks tree-sitter and GitHub network access).
