## Bug and verified focused regression

The Python superclass linker previously assumed the final dotted component in an `import` statement was the bound local name. That is wrong for both `import pkg.base as wire; class Child(wire.Base)` and `import pkg.base; class Child(pkg.base.Base)`. The first binds `wire`; the second binds `pkg`. A class importing `pkg.other as wire` must not inherit from an unrelated `pkg.base.Base`.

Fix: check the bound alias (or unaliased module root), verify the full dotted import tail, and resolve the exact declared superclass FQN. Do not attempt dynamic / runtime inheritance resolution.
