# Iteration 10 — Attested analyzer provenance

## Initial evidence and regression

In previous private Python HA dogfooding the hosted runner's GITHUB_SHA was
different from the separately checked-out analyzer revision. A CI environment
workaround masked the discrepancy. This fix removes the implicit assumption
that hosting runner SHA identifies the installed analyzer.

Base: PR #19 at `344d86f71e4053db953002a06df5d4eee104b007`; stacked draft branch on that exact head.

New `--analyzer-source` and `--expected-analyzer-sha` flags verify the
Git checkout HEAD, clean checkout and byte-for-byte equality between the
Python package files in the checkout and the **actually imported** package.
Without a supplied explicit analyzer pin, the field reports `unavailable`,
not the runner GITHUB_SHA. Partial flags and mismatched packages fail closed.

Local isolated fixture tests: **9 passed** on Python 3.13.5 using real
temporary Git repositories. Full hosted tests and fresh cross-repository
replay: **pending** until workflow completes.

### Scope and limits

The checkout/package byte comparison attests Python source files only,
not interpreter, native dependencies, ignored files or a concurrent mutation
race. Replaying the same analyzer on a second runner establishes reproducibility
but **not semantic correctness**. No change to graph logic/heuristic detection
is claimed. Heuristic smells are not verified architecture violations.
False-positive rates and new screenshots are not yet evaluated.
Do not merge automatically.
