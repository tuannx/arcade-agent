## Verified regression and ground truth

The previous tree-sitter extractor collected same-module bare calls but did not recognize Python `match/case` captures as local bindings. Consequently, it attributed calls through a captured name to an unrelated top-level function of the same name. This is a **verified false call edge on golden fixtures**, not a verified production architectural violation.

Four focused fixtures cover:

1. bare capture `case helper` with an unaffected wildcard control;
2. nested sequence `case [first, *helper]` and mapping `case {"item": helper, **tail}`, with a positive control;
3. class keyword `case Point(x=helper)` and `case (1 | 2) as helper`;
4. dotted value `case Constants.helper` as a positive control (not a capture).

The RED run [CI 41358453179](https://github.com/tuannx/arcade-agent/actions/runs/41358453179) on regression-only commit `37754cf` observed **3 failed, 857 passed, 3 skipped** on Python 3.13. The three failures revealed the missing capture exclusions; the dotted-value positive control passed.

The GREEN run [CI 41358560053](https://github.com/tuannx/arcade-agent/actions/runs/41358560053) on code commit `119d31a` observed **860 passed, 3 skipped** on Python 3.12 and **860 passed, 3 skipped** on Python 3.13. Lint, package and self-analysis jobs passed.

For these four tiny fixtures, the gold labels represent **five false local-call edges removed and three expected true call edges preserved** (8 candidate edges before, 3 expected after). This is fixture-level evidence inferred from the logged RED graph assertions and passing GREEN checks; no estimate of production false-positive rate is made.

Implementation: `_match_capture_names()` walks only capture-bearing tree-sitter pattern operands and ignores class names, class keyword labels, mapping keys and dotted value patterns. The existing conservative `call_coverage: partial` remains unchanged.

## Unsupported cases, limits and next steps

This fix handles local capture bindings and reduces **fixture-observed false positive call edges**. The call graph is still **partial**: dynamic/attribute calls, cross-module or runtime dispatch, nested closure attribution and other name-resolution cases remain unsupported. Match guard control flow is not modeled. Neither 0 heuristic findings nor a higher score proves architectural correctness.

The private Python HA producer/verifier has **not** been rerun against the match-capture patch; the archived private proof is from iteration 10. The YAML-only Action repository cannot provide a Python/Java call-graph baseline. `Concern Overload` on self-analysis remains a low-confidence, non-scoring warning.

Next: add independent fixture assertions for **nested function scopes, comprehensions and match guards** and determine which patterns can be safely resolved without introducing false-positive calls. Revisit private-source coverage only within its private CI. Do not auto-merge stacked PRs.
