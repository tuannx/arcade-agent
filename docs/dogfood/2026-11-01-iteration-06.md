## Reproduced verification gap
The independent verifier compared eight selected JSON fields. It did **not** compare the component list or score-driver details. An altered producer report with a recalculated SHA-256 manifest could therefore pass against an unchanged independent replay.

Three minimal regression controls simulate:
1. Modified `components[*].entities` with a rehashed manifest.
2. Modified `score_drivers` with a rehashed manifest.
3. Removed `components` with a rehashed manifest.

On the old verifier, all three correctly failed their expected rejection tests with `DID NOT RAISE VerificationError`.

## Fix
Compare **every deterministic JSON field**, requiring both producer and independent replay to contain it. Only `timestamp` (different execution time) and `ref` (CI context rather than target architecture) are excluded. The field list is data-driven: future deterministic fields automatically participate; missing fields fail closed.

The two independent hosted replays each compared **23 semantic fields**. This strengthens report consistency, not architectural correctness or human false-positive labels.

## Interpretation
- **Before/after architecture metrics are unchanged.** This was a verifier fix, not an analyzer scoring or parser improvement.
- The reduction of undetected tampering from three regression controls to zero is a deterministic test result, not an estimated real-world detection-rate improvement.
- No human false-positive/false-negative adjudication. No parser unsupported-construct assessment this iteration.
- No real independent LLM sub-agent; the verification actor is a separate CI job with a fresh checkout.
- Target repositories are pinned for reproducible proof; the matrix is not a claim about their newest branch tips.
