## Findings needing follow-up
1. Java's two `Scattered Parasitic Functionality` warnings arise from broad suffix matching of `Configuration` and `Service` across unrelated domain components. This is weak naming evidence, **not a verified architectural violation or confirmed false positive**. Need an intent-aware or concern-stem regression before changing the heuristic.
2. Self-dogfood jobs use differing analysis scopes: one produces 181 entities and another 511. Compare metrics only between runs with identical entrypoint, exclusions and configuration.
3. Git status checks do not prove that ignored files, future races, generated contents or submodule fetching are completely reproducible. Pin SHA and verify the checkout at analysis start; do not claim content attestation.
4. Python private-target CI requires a securely configured read-only credential or an isolated trusted runner. Do not expose private repository data in public artifacts.

## Next action
Build a minimal, reviewable golden fixture for `Service`/`Configuration` suffix-only warnings; triage the Java findings before claiming false-positive reduction. Then add a secure private-Python job or select a public Python target for the next corpus rotation.
