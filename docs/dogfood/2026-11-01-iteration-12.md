## Ground truth and change

Python 3 comprehensions have their own loop-target scope. The conservative
same-module bare-call extractor previously treated calls inside list/set/dict
comprehensions and generators as if they targeted a module function even when
the callee name was bound by a comprehension loop. Comprehension bindings must
also *not* suppress a real call in the enclosing function.

- Added four deterministic fixture tests: direct binding, non-leakage to outer
  scope, nested/generator/destructuring, and set/dict/chained for-clauses.
- Added an explicit comprehension-scope stack to the iterative AST walker.
  Loop targets are collected only for the current comprehension, never for
  the enclosing function. Nested comprehension scopes inherit outer bindings.
- Remains **partial** static call coverage. The algorithm conservatively
  treats a target as bound throughout a comprehension, including first iterable
  evaluation, where Python semantics can differ. Dynamic dispatch, attribute
  calls, closure bodies and deeper name-resolution issues remain unsupported.
- No heuristic smell is upgraded to a verified architecture violation.
  No claim of production FP rate or improved source architecture.
